# CZeroX 组件规范（六种卡 + 状态清单）

基准：`assets/czerox-home.png`（官方主页截图，所有组件样式均可在此图找到实例）。
组件命名是功能性的——gdust 重写时按「这张卡承载什么信息」对号入座，不必逐字照搬 CZero 的业务（清理/F2FS）。

## 六种卡

1. **状态特征卡**（实例：「工作中」绿卡）
   状态色 tint 大底卡（`successTint`）+ 深色粗体标题（用 `text` 纯黑，不用状态色文字）+ 灰副标题（`textSub`）+ **右下角超大半透明状态图标水印**（对勾圆环，`success` 色，溢出卡片边缘裁切）。整卡即状态语义，**不另配 badge、不加角标**。

2. **数据卡**（实例：「今日清理 0 MB」「总清理 0 MB」）
   上标签（`textSub` 13sp）+ 下超大数字（32–40sp Bold 纯黑）。双列网格，无图标、无点缀。数值 0 是合法状态，照常展示。

3. **图表卡**（实例：F2FS 文件系统状态）
   - 标题行 = 彩色小图标（`accent`）+ 标题（Semibold）+ 右侧行内刷新图标（`accent`，可点）
   - 主体 = 左侧环形图（中央大数字 + 下方单位小字）+ 右侧图例列表（8dp 色点 + 标签 + **右对齐数值**）
   - 底部一行 `textSub` 操作提示
   - 环形图分段色用 `chartGreen`/`danger` 等 token，**必须能读出具体数值**（中央数字 + 图例数值），不能只有比例图形。

4. **操作卡**（实例：「立即清理 / 执行全部清理项」）
   标题（Semibold）+ 副标题（`textSub`），整卡可点，按下态用轻微 tint 反馈（同色 6-8% alpha 叠加），不用 ripple 波纹、不用按压缩放。

5. **小数据卡**（实例：微信/QQ/抖音清理）
   同数据卡结构，双列或三列网格；格子数量多时保持等高对齐。

6. **浮动胶囊导航**
   底部居中悬浮胶囊，仅 2–3 个图标位，无文字标签，无常驻大底栏。胶丸底 = 白卡色（深色 = 深灰），可含毛玻璃。

## 页面结构

超大标题页头（左大标题 + 右线性图标操作，图标用 `text` 黑色线性风格）+ 卡片流单列滚动。
**不用 Tab 栏、不用大顶栏背景、不用抽屉**。页面即「标题 + 卡流」。

## 状态清单（每个组件动手前过一遍）

- 默认 / 按下（tint 反馈）/ 禁用（数值区显示「—」，不置灰整卡）
- 加载：卡内 shimmer 或刷新图标旋转，**不整页转圈**
- 错误：卡内一行红字（`danger`）+ 重试入口，**不弹窗轰炸**
- 空态：数值 0 是合法状态正常展示，**不做「暂无数据」大插画**
- 深色模式：见 tokens.md 深色小节
